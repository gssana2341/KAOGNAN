# KaoNgan · ระบบเช็คอินเข้างานด้วย QR

เช็คอิน/เอาท์ด้วยการสแกน QR ที่ทำงาน · แยกบัญชีรายคน · ขอลาออนไลน์ · ออก Excel · เลือกพื้นหลังน่ารัก ๆ ได้
ใช้ได้ทั้งมือถือและคอม (เว็บแบบ responsive + ติดตั้งเป็น PWA ได้)

## เริ่มใช้งาน

```bash
npm install
npm start          # เปิด http://localhost:3000
```

- แอดมินเริ่มต้น: `admin` / `admin1234` — ระบบบังคับให้เปลี่ยนรหัสผ่านตอนล็อกอินครั้งแรก
- อยากลองก่อนด้วยข้อมูลตัวอย่าง: `npm run seed` (พนักงาน 6 คน รหัสผ่าน `demo1234` พร้อมประวัติย้อนหลัง 4 สัปดาห์)
- ทดสอบอัตโนมัติ: `npm test`

## ขั้นตอนตั้งต้น (แอดมิน)

1. **จัดการ → ตั้งค่า & QR**: ใส่ชื่อบริษัท เวลาเริ่ม/เลิกงาน เวลาผ่อนผันมาสาย วันทำงาน
2. กด **เปิดหน้าจอ QR / พิมพ์** แล้วพิมพ์ไปติดที่ทำงาน (หรือเปิดค้างบนแท็บเล็ต)
3. **จัดการ → พนักงาน → เพิ่มพนักงาน** ตั้งรหัสผ่านชั่วคราวให้ พนักงานจะต้องเปลี่ยนเองตอนเข้าครั้งแรก
4. พนักงานล็อกอิน → กดปุ่มสแกนใหญ่ → เล็งกล้องไปที่ QR ที่ทำงาน (เข้างานและออกงานใช้ QR เดียวกัน)

## QR ที่ทำงาน — เลือกได้ 2 แบบ

| แบบ | เหมาะกับ | หมายเหตุ |
|---|---|---|
| **QR ติดผนัง** (ค่าเริ่มต้น) | ร้านเล็ก ๆ ที่ไว้ใจกัน | พิมพ์ครั้งเดียว แต่ถ้าใครถ่ายรูป QR ไปสแกนจากที่บ้านก็ทำได้ |
| **QR เปลี่ยนทุกครั้ง** | ต้องการกันการเช็คอินแทน/จากที่บ้าน | แสดงบนจอ/แท็บเล็ตที่ทำงาน QR เปลี่ยนทุก 15–600 วินาที (ค่าเริ่มต้น 60) |

“สร้าง QR ใหม่” ทำให้ QR เก่าที่พิมพ์ไว้ใช้ไม่ได้ทันที (ใช้เมื่อ QR รั่วไหล)

### พิมพ์ใบ QR

จัดการ → ตั้งค่า & QR → **เปิดหน้าจอ QR / พิมพ์** จะได้โปสเตอร์พร้อมวิธีสแกน 3 ขั้นตอน เลือก **แนวตั้ง/แนวนอน** และ **A4/A5** ได้
แล้วกด “พิมพ์” (ระบบตั้งขนาดและแนวกระดาษใน Print ให้เอง ถ้าเครื่องพิมพ์ถามให้เลือกขนาดตามที่เลือกไว้) · โหมด “QR เปลี่ยนทุกครั้ง” พิมพ์ไม่ได้ เพราะ QR หมดอายุ

## กล้องมือถือต้องใช้ HTTPS

เบราว์เซอร์อนุญาตให้ใช้กล้องเฉพาะบน `https://` หรือ `localhost` เท่านั้น ถ้าเปิดผ่าน `http://192.168.x.x:3000` ปุ่มสแกนจะเปลี่ยนเป็น
“ถ่ายรูป QR แทน” (ยังเช็คอินได้ แต่ไม่ใช่กล้องสด) วิธีเปิด HTTPS:

- **ทดสอบในวง Wi-Fi เดียวกัน:** `npm run cert` (ต้องมี `openssl` — มากับ Git for Windows) แล้ว `npm start` ใหม่ → เปิด `https://<ไอพีเครื่องนี้>:3000` บนมือถือ ครั้งแรกกด “ขั้นสูง → ดำเนินการต่อ”
- **ใช้งานจริง:** วางหลัง HTTPS ที่ถูกต้อง เช่น Cloudflare Tunnel (ฟรี), Caddy, nginx + Let's Encrypt หรือโฮสต์บน VPS/Render/Railway
  (ถ้าอยู่หลัง proxy ตั้ง `TRUST_PROXY=1` เพื่อให้ตัวจำกัดการล็อกอินผิดเห็น IP จริง)

## ดีพลอยขึ้นเว็บจริง

ระบบมี 2 โหมดฐานข้อมูล ใช้โค้ดชุดเดียวกัน: ถ้าตั้ง `TURSO_DATABASE_URL` จะใช้ฐานข้อมูลออนไลน์ [Turso](https://turso.tech) (SQLite บนคลาวด์) ถ้าไม่ตั้ง จะใช้ไฟล์ SQLite ในเครื่อง

### ทางที่ 1: Vercel + Turso (ไม่ต้องดูแลเซิร์ฟเวอร์เอง)

Vercel ไม่มีดิสก์ถาวร จึงเก็บข้อมูลในไฟล์ไม่ได้ — ต้องใช้ Turso คู่กัน

1. **สร้างฐานข้อมูล Turso:** สมัคร turso.tech → Create Database (ตั้งชื่อ `kaongan`, เลือก location ใกล้ไทย เช่น สิงคโปร์)
   แล้วคัดลอก **Database URL** (หน้าตา `libsql://kaongan-xxxx.turso.io`) และสร้าง **Auth Token** (Create Token) เก็บไว้
2. **Vercel → โปรเจกต์ → Settings → Environment Variables** เพิ่ม 3 ตัว (ติ๊ก Production):

   | ชื่อ | ค่า |
   |---|---|
   | `TURSO_DATABASE_URL` | URL จากข้อ 1 |
   | `TURSO_AUTH_TOKEN` | Token จากข้อ 1 |
   | `ADMIN_PASSWORD` | – | รหัสผ่านแอดมิน (ชื่อผู้ใช้ `admin`) ใช้ตอนสร้างระบบครั้งแรก และถ้าตั้งทีหลังก็มีผลตราบใดที่แอดมินยังไม่เคยเปลี่ยนรหัสเอง · ไม่ตั้ง: เครื่องตัวเอง = `admin1234`, production = สุ่มแล้วพิมพ์ใน log ครั้งเดียว |
| `RESET_ADMIN` | – | ใส่ `1` คู่กับ `ADMIN_PASSWORD` เพื่อ **รีเซ็ตรหัสแอดมินกรณีลืม** (ใช้เสร็จแล้วให้ลบตัวแปรนี้ทิ้ง) |

3. **Deployments → ⋯ → Redeploy** (ต้อง redeploy ให้ตัวแปรมีผล)
4. เปิด `https://<โดเมนของคุณ>/api/health/db` ต้องเห็น `{"ok":true,"database":"turso"}`
   (ถ้าไม่ใช่ จะมีข้อความบอกว่าขาดอะไร) แล้วล็อกอินด้วย `admin` + `ADMIN_PASSWORD`

หมายเหตุ: `vercel.json` ตั้งให้ฟังก์ชันรันที่สิงคโปร์ (`sin1`) — ถ้า Vercel ไม่อนุญาตแพ็กเกจของคุณ ให้ลบบรรทัด `regions` ·
แพ็กเกจ Hobby ของ Vercel ตามเงื่อนไขการใช้งานเป็นแบบ **ไม่ใช้เชิงพาณิชย์** ถ้าใช้ในบริษัทจริงให้ตรวจเงื่อนไข/แพ็กเกจล่าสุดของ Vercel และ Turso

### ทางที่ 2: เซิร์ฟเวอร์ที่รัน Node ตลอด (Render / Railway / Fly.io / VPS)

ใช้ไฟล์ SQLite ในดิสก์ถาวร ไม่ต้องมี Turso

| โฮสต์ | วิธี |
|---|---|
| **Render** | New + → **Blueprint** → เลือกรีโปนี้ (ใช้ `render.yaml`) แล้วตั้ง `ADMIN_PASSWORD` — ดิสก์ถาวรต้องใช้แพ็กเกจเสียเงิน ถ้าใช้ฟรี ข้อมูลจะหายทุกครั้งที่รีสตาร์ต/ดีพลอย |
| **Railway / Fly.io** | ดีพลอยจาก `Dockerfile` ผูก Volume ไปที่ `/data` แล้วตั้ง env ด้านล่าง |
| **VPS** | `git clone` → `npm ci --omit=dev` → `NODE_ENV=production npm start` หลัง Nginx/Caddy ที่เปิด HTTPS (ส่ง `/` ทั้งหมดไปที่พอร์ต Node ไม่ใช่เฉพาะ `/api`) |

env บนโฮสต์แบบนี้: `NODE_ENV=production`, `ADMIN_PASSWORD=<รหัสแอดมินของคุณ>`, `TRUST_PROXY=1`, `DATA_DIR=<โฟลเดอร์ของดิสก์ถาวร>`
ตรวจว่าขึ้นแล้ว: เปิด `/healthz` ต้องเห็น `ok`

> ถ้าไม่ตั้ง `ADMIN_PASSWORD` ในโหมด production ระบบจะ **สุ่มรหัสแอดมินแล้วพิมพ์ใน log ครั้งเดียว** (ไม่ใช้ `admin1234` เพื่อกันคนแปลกหน้าล็อกอินตัดหน้า)

## Excel

**จัดการ → เวลาเข้างาน & Excel** เลือกช่วงวันที่ (และเลือกรายคนได้) แล้วกด “ดาวน์โหลด Excel” ได้ 3 ชีต:

- **สรุปรายคน** — วันทำงานตามกำหนด / มา / สาย (ครั้ง, นาที) / ลา / ขาด / ชั่วโมงรวม
- **รายวัน** — เวลาเข้า-ออกทุกวัน พร้อมสถานะ ปกติ·สาย·ลา·ขาด
- **ใบลา** — ใบลาทั้งหมดในช่วงนั้นพร้อมสถานะ

“ขาด” = วันทำงานที่ผ่านมาแล้วโดยไม่มีเวลาสแกนและไม่มีใบลาที่อนุมัติ · วันที่ใน Excel เป็น ค.ศ. (dd/mm/yyyy) ส่วนหน้าเว็บแสดง พ.ศ.
ลืมสแกน? แอดมินกดที่แถวในตารางเพื่อแก้เวลา/เพิ่มหมายเหตุได้

## การตั้งค่าผ่าน environment variables (ไม่บังคับ)

| ตัวแปร | ค่าเริ่มต้น | ใช้ทำอะไร |
|---|---|---|
| `PORT` | `3000` | พอร์ต |
| `NODE_ENV` | – | ตั้งเป็น `production` บนเซิร์ฟเวอร์จริง (ไม่ใช้รหัสแอดมินเริ่มต้นที่เดาง่าย) |
| `ADMIN_PASSWORD` | – | รหัสแอดมินตอนสร้างระบบครั้งแรก (ไม่ตั้ง: เครื่องตัวเอง = `admin1234`, production = สุ่มแล้วพิมพ์ใน log) |
| `DATA_DIR` | `./data` | ที่เก็บไฟล์ฐานข้อมูล SQLite (`kaongan.db`) เมื่อไม่ได้ใช้ Turso — **สำรองโฟลเดอร์นี้** |
| `TURSO_DATABASE_URL` / `TURSO_AUTH_TOKEN` | – | ใช้ฐานข้อมูลออนไลน์ Turso แทนไฟล์ (จำเป็นบน Vercel) |
| `TRUST_PROXY` | – | ตั้งเป็น `1` เมื่ออยู่หลัง reverse proxy |
| `CORS_ORIGINS` | – | origin ของแอปมือถือ (คั่นด้วย `,`) ที่อนุญาตให้เรียก API |
| `TZ_OFFSET_MIN` | `420` | เขตเวลา (นาทีจาก UTC) — ค่าเริ่มต้นคือประเทศไทย |
| `MIN_STAY_SEC` | `60` | ห่างกันอย่างน้อยกี่วินาทีระหว่างเข้า→ออก (กันสแกนซ้ำ) |

## โครงสร้าง

```
server/    Express + SQLite/Turso (libSQL), API ทั้งหมดอยู่ใต้ /api (Bearer token) — app.js = ตัวแอป, index.js = รันเป็นเซิร์ฟเวอร์
api/       จุดเข้าของ Vercel (รัน server/app.js เป็น serverless function)
public/    หน้าเว็บ (ไม่ต้อง build): js/views/* แต่ละหน้า, bg/* พื้นหลัง SVG, manifest + service worker
scripts/   seed-demo, make-cert, make-icons (ไอคอนแอป), build-icons (ไอคอน UI), copy-vendor
docs/      image-prompts.md — prompt ทำมาสคอต/ไอคอน/พื้นหลัง
test/      ทดสอบ API ครบเส้นทางหลัก
```

## ปรับหน้าตา / ใส่รูปของตัวเอง

มาสคอตแมว ไอคอนแอป และพื้นหลังที่ให้มาเป็น SVG ที่วาดไว้ในตัว ถ้าอยากได้รูปสวย ๆ จาก AI วางไฟล์ตามตำแหน่งได้เลยโดยไม่ต้องแก้โค้ด
ดู prompt สำเร็จรูป ขนาดไฟล์ และขั้นตอนใน [docs/image-prompts.md](docs/image-prompts.md)

- มาสคอตจาก AI: วางรูปใน `art-source/mascot/` แล้ว `npm run mascot` (ลบพื้นหลัง + ย่อให้อัตโนมัติ)
- ไอคอน UI ทั้งหมดใช้ [Lucide](https://lucide.dev) (ISC) — เพิ่มไอคอนใหม่: ใส่ชื่อใน `scripts/build-icons.js` แล้ว `npm run icons`

## ต่อยอดเป็นแอป

เว็บเรียก API ผ่าน `Authorization: Bearer …` ล้วน ๆ ไม่พึ่ง cookie จึงห่อเป็นแอปได้ตรง ๆ (เช่น Capacitor):
ตั้ง `window.KN_API_BASE` ใน `public/config.js` เป็นที่อยู่เซิร์ฟเวอร์ และเพิ่ม origin ของแอปใน `CORS_ORIGINS`
แล้วค่อยเปลี่ยนตัวสแกนเป็นปลั๊กอินกล้องเนทีฟได้ถ้าต้องการ (ปัจจุบันใช้ jsQR ในเบราว์เซอร์)
